# دیدبان دارو — Pharma Analytics

داشبورد فارسی و راست‌به‌چپ بازار دارویی ایران با پاسخ به هر ده سؤال تمرین. مقایسه پیش‌فرض **۱۴۰۱ → ۱۴۰۲** است؛ داده‌های ۱۴۰۳ و ۱۴۰۴ نیز قابل انتخاب‌اند.

## اجرا

در ویندوز، `launch_dashboard.cmd` را اجرا کنید تا سرور و مرورگر باز شوند. یا از ریشه همین پوشه:

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory docs
```

سپس مرورگر را روی `http://127.0.0.1:8765` باز کنید. فایل HTML را با دوبارکلیک اجرا نکنید؛ Worker و دریافت دیتابیس به HTTP نیاز دارند. مرورگر باید WebAssembly و DecompressionStream را پشتیبانی کند. هیچ نصب Python package برای نمایش لازم نیست.

## انتشار در GitHub Pages

**انتشار روی مخزن تعیین‌شده:** در ویندوز `publish_to_github.cmd` را اجرا کنید. اسکریپت commit/push معمول Git را انجام می‌دهد، ورود استاندارد GitHub را به خود Git می‌سپارد و در صورت دسترسی، Pages را روی `main /docs` فعال می‌کند. رمز یا توکن را در چت یا کد وارد نکنید. اگر API تنظیم Pages اجازه نداد، صفحه تنظیمات را برای انتخاب همین گزینه‌ها باز می‌کند. هیچ force-push انجام نمی‌شود.

روش دستی:

1. محتویات این پوشه را با Git در مخزن قرار دهید (فایل SQL بزرگ‌تر از محدودیت آپلود وب است).
2. در `Settings → Pages`، بخش `Build and deployment` را روی `Deploy from a branch` بگذارید.
3. شاخه `main` و پوشه `/docs` را انتخاب و ذخیره کنید.
4. پس از اتمام انتشار، لینک نمایش‌داده‌شده در Pages را برای ارزیاب بفرستید؛ لینک مخزن را هم برای بررسی کد و داده بدهید.

نمونه آدرس (جایگزین نام واقعی حساب و مخزن شود): `https://USERNAME.github.io/REPOSITORY/`.

همه مسیرهای برنامه نسبی‌اند تا زیرمسیر مخزن نیز کار کند. فونت، ECharts و sql.js همراه پروژه هستند؛ برنامه در زمان اجرا به CDN وابسته نیست. فایل دیتابیس مرورگر حدود ۹ MB فشرده است. فیلترها به‌صورت پارامتر SQL در یک Web Worker اجرا می‌شوند تا رابط کاربری قفل نشود. اطلاعات اتصال یا رمز دیتابیس در مرورگر وجود ندارد.

**مخزن مقصد:** https://github.com/abbas-asghari/Pharma-Analytics

بسته برای انتشار در Pages آماده است. اتصال فعلی افزونه GitHub خواندن مخزن را مجاز می‌داند، اما نوشتن فایل را با HTTP 403 رد کرده است. تا اجرای موفق انتشار، سایت عمومی منتشرشده محسوب نمی‌شود.

## معماری و تحویل‌ها

```text
Excel 1401–1404
  └─ Python cleaning → PostgreSQL snapshot + complete SQLite
       └─ scripts/build_web_data.py → annual browser SQLite
            └─ sql.js / Web Worker → ECharts + downloadable CSV/PNG
```

| مسیر | محتوا |
|---|---|
| `docs/index.html`, `style.css`, `app.js` | رابط داشبورد |
| `docs/worker.js`, `queries.js` | موتور کوئری و SQL واقعی فیلترها |
| `docs/data/dashboard.sqlite.gz` | دیتابیس سالانه مورد استفاده مرورگر |
| `docs/data/metadata.json` | شمار ردیف‌ها و کنترل جمع‌های چهار سال |
| `data/pharma_1401_1404.sql` | تمام جدول‌ها و داده‌ها برای بازسازی PostgreSQL |
| `sql/analytical_queries.sql` | پاسخ SQL ده سؤال روی دیتابیس مرورگر |
| `sql/postgresql_queries.sql` | نسخه SQL برای مدل اصلی PostgreSQL |
| `pipeline/` | کدهای اصلی تبدیل Excel و مستندات مدل |
| `scripts/` | ساخت دیتابیس مرورگر، کنترل نتایج و بسته‌بندی |
| `evidence/` | گزارش آزمون، ۱۴ نمودار کامل SVG و تصاویر مرورگر |

فایل SQL شامل `CREATE TABLE`, `COPY`, کلیدها، ایندکس‌ها و viewهاست؛ یک snapshot قابل بازیابی است و خروجی مستقیم ابزار `pg_dump` نیست. برای بازیابی، از `psql` استفاده کنید:

```powershell
createdb -U postgres pharma_analytics
psql -U postgres -d pharma_analytics -v ON_ERROR_STOP=1 -f data/pharma_1401_1404.sql
psql -U postgres -d pharma_analytics -v ON_ERROR_STOP=1 -f sql/postgresql_queries.sql
```

برای تهیه dump رسمی پس از بازیابی:

```powershell
pg_dump -U postgres -d pharma_analytics --schema=pharma --format=plain --file=pharma_dump.sql
```

بازیابی روی PostgreSQL زنده در محیط ساخت این بسته اجرا نشده است. فایل SQL از نظر شمار ردیف‌ها و جمع مقادیر کنترل شده است.

## پوشش سؤال‌ها

| سؤال | بخش | نمایش |
|---|---|---|
| ۱ | داشبورد بازار | دو نمودار مبلغ/تعداد سالانه و جدول مقادیر |
| ۲ و ۳ | داشبورد بازار | نمودار رشد درصدی جدا برای مبلغ و تعداد |
| ۴ و ۵ | تأمین‌کنندگان | دو نمودار با ترتیب ثابت بر اساس مبلغ سال مقایسه؛ جدول تغییر مطلق و درصدی |
| ۶ و ۷ | شرکت‌های پخش | دو نمودار با ترتیب ثابت بر اساس تعداد سال مقایسه؛ جدول تغییر مطلق و درصدی |
| ۸ | ATC | نمودار مبلغ و تعداد برای ATC سطح اول |
| ۹ | ATC | دو نمودار درصدی انباشته؛ مبلغ و تعداد |
| ۱۰ | وضعیت نسخه | دو نمودار و جدول OTC/Rx |

هر نمودار دکمه دانلود PNG دارد. جدول‌ها CSV با اعداد مقیاس‌نشده و وضعیت فیلترها صادر می‌کنند. انتخاب شرکت با تایپ و انتخاب از پیشنهادها انجام می‌شود. فیلترها بعد از زدن «اعمال فیلتر» اجرا می‌شوند.

## فرض‌ها و کیفیت داده

- ورودی فایل `1401-1404.xlsx` ارائه‌شده توسط صاحب پروژه است. **لینک دانلود رسمی و دوره پوشش دقیق باید برای تحویل نهایی مستند شود**؛ این بسته از روی نام فایل، اصالت رسمی منبع را تأیید نمی‌کند.
- مدل اصلی: یک `fact_sales` و دو بُعد `dim_product` و `dim_company`. نقش‌های تأمین‌کننده، پخش، تولیدکننده و صاحب برند مستقل‌اند. IRC ممکن است چند نسخه مشخصات داشته باشد؛ شمار محصول با `COUNT(DISTINCT irc)` است.
- فروش ریالی = فروش بر پایه قیمت مصرف‌کننده، به ریال. همت در نمودار = ۱۰^۱۳ ریال. فروش عددی به معنی تعداد واحد گزارش‌شده است، نه بسته یا DDD.
- ۸۲۹٬۰۱۵ ردیف منبع به ۲۹۶٬۲۳۱ ردیف گزارش سالانه تبدیل شده است. کلید تجمیع: سال، نسخه محصول، تأمین‌کننده، پخش. این کار مبلغ و مقدار را حفظ می‌کند؛ فایل اصلی همچنان تمام ردیف‌ها را دارد.
- تنها ۱۴۰۳ ستون ماه دارد. ماه در نسخه مرورگر استفاده نمی‌شود؛ برای بقیه سال‌ها در مدل اصلی NULL است. کامل‌بودن دوره ۱۴۰۴ هنوز از مرجع انتشار تأیید نشده است.
- ATC نامعتبر/خالی در گروه «نامشخص» باقی می‌ماند؛ در ۱۴۰۱، ۸۳۲ ردیف منبع چنین وضعیتی دارند. مقدار OTC در داده موجود ثبت شده؛ خالی احتمالی هرگز Rx فرض نمی‌شود.
- NULL عددی صفر نمی‌شود. SUM مقادیر موجود را جمع می‌کند؛ تعداد مقادیر گمشده ثبت می‌شود. برای **شرکتی که هیچ ردیفی در سال پایه ندارد**، مقدار پایه طبق تمرین صفر است.
- فروش منفی و صفر حذف نشده‌اند. سهم درصدی بر فروش خالص محاسبه می‌شود؛ با فروش منفی ممکن است یک سهم منفی یا بیش از ۱۰۰٪ شود. مخرج صفر به‌صورت تعریف‌نشده نمایش داده می‌شود.
- رشد با پایه صفر یا منفی تعریف نمی‌شود. تغییر مطلق همچنان گزارش می‌شود. همت یا مقدار گرد‌شده نمودار مبنای محاسبه رشد نیست.
- فیلترها بر هر دو سال و تمام کوئری‌ها اعمال می‌شوند؛ «سهم» در این حالت سهم از مجموعه فیلترشده است. با دکمه بازگشت به حالت تمرین، تمام فیلترها پاک می‌شوند.
- عناوین شرکت فقط از لحاظ حروف/فاصله استاندارد شده‌اند. ادغام املایی یا حقوقی بدون مرجع انجام نشده است.
- SQLite و JavaScript در مقادیر اعشاری اختلاف جزئی ممیز شناور دارند. برای حسابرسی دقیق از NUMERIC در PostgreSQL استفاده شود؛ اختلاف چند ریال در جمع‌های بزرگ ممکن است.

## بازتولید

کدهای `pipeline/` از اکسل، SQLite کامل و SQL PostgreSQL می‌سازند. سپس:

```powershell
python scripts/build_web_data.py --source PATH_TO_COMPLETE_SQLITE
```

فایل خروجی موجود عمداً بازنویسی نمی‌شود؛ برای بازسازی، فقط فایل تولیدشده `docs/data/dashboard.sqlite` را پس از نگه‌داشت نسخه قبلی حذف کنید. نسخه فشرده و metadata در ادامه ساخته می‌شوند.

کنترل‌ها در `scripts/validate_dashboard.py` با استفاده از SQL واقعی برنامه انجام شده‌اند: ۵۴ مقایسه کوئری با داده اصلی، سناریوهای فیلتر شرکت/ATC/OTC/منشأ/جست‌وجو/چهار سال، تطبیق ترتیب مستقل ده شرکت برتر، جمع گروه‌ها و سلامت دیتابیس. برای اجرای مجدد، مسیر دیتابیس منبع را با `--source` مشخص کنید. Node.js و Python لازم‌اند.

## یافته اولیه (حالت اصلی تمرین)

ارزش فروش ۱۴۰۲ نسبت به ۱۴۰۱ **۵۳٫۸۴٪ افزایش** و تعداد فروش **۶٫۳۶٪ کاهش** داشته است. این اختلاف به‌تنهایی تورم خالص یا تغییر مصرف درمانی را اثبات نمی‌کند؛ تغییر قیمت و ترکیب محصول نیز ممکن است مؤثر باشد.

## طراحی و نمایش داده

رابط از فونت محلی Vazirmatn و آیکون‌های رسمی Lucide استفاده می‌کند. مشخصات اجزا در `DESIGN_SYSTEM.md` و نمونه تعاملی در `docs/design-system.html` است.

بنرهای کیفیت داده به بخش روش تحلیل منتقل شده‌اند. گروه نامشخص در نمودارها و خروجی CSV گروه‌های ATC نمایش داده نمی‌شود؛ سهم درصدی بر مبنای فروش داروهای دارای کد معتبر ATC محاسبه می‌شود. رکوردهای منبع، SQL و جمع کل بازار تغییری نکرده‌اند. خروجی SQL ممکن است شامل گروه نامشخص باشد.
